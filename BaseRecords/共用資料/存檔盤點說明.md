## 據點判定

先讀取 Git 忽略的 `expedition-player.local.json`，再以下列關聯篩選據點：

1. 以建築的 `build_player_uid` 找出目標玩家親建設施所屬據點。
2. 由該據點的 `group_id_belong_to` 確定唯一公會。
3. 納入同一公會的全部 `BaseCampSaveData`，再依存檔排列編為第一至第六據點。
4. 正式紀錄只保留去識別化後的建築、工作帕魯與固定指派摘要。

## 數量與名稱規則

- 建築數量只計入所屬據點 ID 相符的功能建築。
- 屋頂、地基、牆、柱、樓梯、裝飾、告示牌、散落物與帕魯蛋等不列入據點功能設施表。
- 帕魯數量取自各據點 `WorkerDirector` 指向的工作容器；空格不計入。
- 遊戲顯示星級以存檔內部 `Rank - 1` 換算，例如內部 Rank 5 記為 4 星。
- 家畜牧場、配種牧場及固定工作設施的帕魯配置取自 `WorkAssignMap`，不只依暱稱推測。
- 帕魯內部名稱透過[帕魯索引](配種資料/帕魯索引.csv)轉為繁體中文。
- 建築內部名稱參考 [Pocketpair 官方 Technology ID 清單](https://docs.palworldgame.com/settings-and-operation/technologyids/)；專案沿用既有用語，例如「蓄電器」、「大型廚房」及「低溫保鮮飼料箱」。
